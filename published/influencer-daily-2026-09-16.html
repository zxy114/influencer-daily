📝 推文原文
How to build great evals - part 10. Measure the steps, not just the result. Much like high school math, it isn't sufficient just to get the right answer, the steps to get there are critical. Two agent trajectories might produce the same answer (42), but one of them searches…
🇨🇳 中文翻译：如何构建高质量 Evals（系列第 10 篇）—— 衡量"步骤"，而不仅仅是"结果"。就像高中数学，光给出正确答案远远不够，到达答案的"过程"才是关键。两条 Agent 轨迹可能都得出 (42) 这个结果，但其中一条会搜索、推理、交叉验证……
💡 如何应用
在为 Coding Agent / 客服 Agent / 研究 Agent 写 Eval 时别只看 final answer；把"过程轨迹"也拆成可打分的中间节点（搜索了几次？调用了哪个工具？中间推理是否过 critical？）。这样你能定位"为什么同一个结果，A 模型比 B 模型贵 10 倍 token 但更靠谱"。Agent 产品经理、Eval 工程师必读。

来源：@trq212（Claude Code 团队）
📝 推文原文
I was not expecting things to go this way, but I think MCPs are better than CLIs for most integrations. The models have gotten much better at tool calling, we can defer tools & MCP is now stateless. If you need to compose/filter data, add params like query to your MCP tools.
🇨🇳 中文翻译：没料到事情会发展成这样，但我认为大多数集成场景下 MCP 都比 CLI 更合适。模型在工具调用上已经强很多了，我们可以延迟加载工具，而且 MCP 现在是无状态的。如果你需要组合/过滤数据，给 MCP 工具加上 query 这样的参数即可。

1️⃣3️⃣ Zara Zhang：识别 Astra 的"被动等指令"陷阱 —— Prompt 迭代技巧
💡 Prompt 模板 🔧 工作流 6/10
来源：@zarazhangrui
📝 推文原文
Anyone else notices this problem with Astra? Astra: I have done X. Me: This is wrong, you should do Y instead. Astra: You're right. I should do Y. Me: ... Why doesn't it just go and do Y, like the other models??
🇨🇳 中文翻译：有人注意到 Astra 的这个问题吗？Astra：X 任务做完了。我：这不对，你应该做 Y。Astra：你说得对，我应该做 Y。我：…… 那你倒是去做啊？？？别的模型都会直接做完。
💡 如何应用
发现 Astra（以及类似模型）在被指出错误后只"承认"而不"执行"时，换个 prompt 模式：别再说 "you should do Y"，直接说 "do Y now and show me the result, no acknowledgement needed"。把"指出问题"和"执行指令"分开写在同一个 prompt 里。重模型用户、Agent 调试者必读（1.7K 点赞 / 447K 浏览，高频痛点）。
